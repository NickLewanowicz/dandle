5 · Design framework v2.2 — the rules these frames follow (cascade to every future screen)

Entity hierarchy flows top-down. The child is the top-level entity — a timer always belongs to a child, never exists globally — so the child selector sits above the actions. The UI communicates entity priority through layout, without ever making the user "select a child first." Static identity chrome (child name, sync state) may sit above the buttons because it never shifts; dynamic/live elements (timer cards, forms, history) may not — they would move the buttons depending on app state and break muscle memory. This decision cascades to every future screen: entities render above their dependents.
Buttons = pinned instruments, all six, always. A 2×3 grid directly under the header in a fixed position. Running state outlines a button; buttons never move or resize.
Card = a live entity, and can contain inputs. Running timers render as scene cards sized to their fields (sleep: note · pumping: amount + note · feeding: type + method + amount + note). An in-progress form (diaper) is also a card. Cards live below the buttons, never above. When the entity's run ends, the card is replaced by a History row — cards never represent completed history.
Stopping happens on the card. ✓ saves (attaching the note). Under 10 s the save silently discards — unchanged semantics. No separate guard dialog.
History = the record pane. An infinite-scroll pane anchored to the bottom of the dashboard: chunked queries, proactive prefetch, no pager buttons. Row anatomy is fixed: chip → name → notes → duration → range → sync.
Sheet = transient input only. A sheet may cover the buttons only to capture input (create/edit) and always clears back to the identical layout. History is not a sheet-input surface — editing history opens an edit form (E1/E3 pattern), never a stacked history sheet.
Scenes are subdued backgrounds, never content. Scene art sits behind solid card surfaces; accessibility contrast holds in light and dark. Each activity owns exactly one motif (sleep = night sky, pumping = milk, feeding = bottles).
Motion = ambient, out of the thumb path. Drift/twinkle/float loops only; honors reduce-motion; nothing bounces under interaction.
